## F-01：超过 20 个进程时流量采样失效

严重性：影响仪表盘数据正确性；不等同于代理转发失败。

位置：`Sources/CodexProxyLauncherCore/TrafficSampler.swift` 的 `sample`、`runCommand` 和界面数据接线。

实测证据：

1. Codex 进程树一次快照有 33 个 PID。
2. 单独选择有 TCP 连接的子进程，`nettop -P -L 1 -x -J bytes_in,bytes_out -p <PID>` 返回有效计数。
3. 主进程加该子进程同样返回有效计数。
4. 把完整 33 个 PID 依照生产代码的方式逐一追加 `-p`，命令返回 **64**，标准输出第一行为 `Attempting to monitor too many process ids, limit is 20`。
5. 生产采样未处理命令失败，将帮助文本交给 CSV 解析，得到空计数；核心实测 `observedProcesses=0`，GUI 的速率和曲线持续为 0，累计流量停止增长。

`git diff 53020ae HEAD -- Sources/CodexProxyLauncherCore/TrafficSampler.swift` 无差异：它是此前已存在、由本轮真实环境验证暴露的缺陷，不能称为 0.3.0 新引入的回归。

现有 4 项 TrafficSampler 单元测试验证合成 CSV、PID 树、连接计数及累计算法，没有执行超过 20 PID 的真实 nettop 调用。因此 21 项全绿不能证明该功能可用。

建议独立修复：将 nettop 调用按最多 20 PID 分批后合并，或使用单次采样再过滤所需 PID；明确区分“命令失败/采样不可用”与“真实 0 流量”；覆盖超过 20 PID 和命令返回非零的回归用例，并在真实进程树和 GUI 上复验。当前验证阶段未修改应用代码。

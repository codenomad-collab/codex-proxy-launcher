## 基线与问题

- GitHub `origin/main` 与本机主分支均为 `53020aed1aea6d6085932bf729d6992c797fca9c`，代码版本 0.2.0。
- 旧启动器只向 Electron 与遵循环境变量的子进程注入代理。原生电脑控制服务访问 `chatgpt.com/backend-api/aura/site_status` 超时。
- 本机未开启系统代理。原生默认 URLSession 请求约 5 秒超时；显式本机 Clash 请求返回 HTTP 401，证明代理链路可达，未证明登录成功。

## 实施范围

- 普通启动逻辑保留，官方应用仍按 Bundle ID 定位。
- 新增原生网络与显式代理对比、OpenAI 域名 PAC、回环 PAC 服务及受令牌保护的停止/会话交接接口。
- 可选管理员助手仅修改活动网络的 PAC 字段。已有代理不覆盖；第三方修改不回滚。
- 管理员助手为会话进程，不安装 LaunchDaemon，不修改授权数据库、系统证书或官方客户端文件。
- 快照与控制令牌由管理员拥有，当前用户仅获读取 ACL。报告不包含令牌、密码或订阅信息。

## 当前运行与后续交接

安装位置保持原来的 `codex-proxy-launcher/dist/Codex 代理启动器.app`，已是 0.3.0。官方 Codex / ChatGPT 客户端仍在运行，兼容助手的所有者是新版启动器，重启 Codex 不应结束兼容代理。

为排查连接缓存曾单独结束 `SkyComputerUseService`，当时客户端没有自动重建该服务，后续电脑控制调用仍超时。随后用户通过启动器重启了 Codex：已确认新的官方客户端与电脑控制服务进程均出现，兼容代理保持运行，默认原生探测约 846 ms 返回 HTTP 401，显式代理约 802 ms 返回 401。

重启后当前会话没有重新加载电脑/Chrome 控制工具，工具可用性更新明确移除了该命名空间。因此真实 Chrome 页面仍未验收，不得据原生探测通过宣称页面操作已恢复。

用户随后在本对话重新选择了电脑插件，执行接口仍未出现。只读核对显示：本机 `computer-use`、`chrome`、`unified-computer-use` 三个插件均为启用；客户端日志记录原生电脑服务可用及 `cua_repl` 就绪，但就绪记录对应另一对话，不能代替本对话的工具可用性。当前插件配置和进程就绪并不足以完成页面操作。本对话连接状态是否陈旧仍属于推断，未证明是唯一根因。

回家后复测默认原生请求约 1624 ms、显式代理约 4454 ms，均返回 HTTP 401。结论仅限未认证请求可达。按照 [官方浏览器扩展排查说明](https://learn.chatgpt.com/docs/chrome-extension)，下一步改为在新对话选择 `@Chrome` 后进行实际页面验收；不再重复让用户在同一旧对话重选插件。

### 实际浏览器调用补验与更正

用户继续明确选择内置 Browser 后，找到了本机动态生成的 Browser 技能说明（位于 `.codex/.tmp/bundled-marketplaces/openai-bundled/plugins/browser/skills/control-in-app-browser/SKILL.md`）。缓存插件的空 `skills/` 目录不能证明运行时不可初始化，先前只根据接口清单和空目录推断不可用不够完整。

本轮已按照该说明，通过官方 Browser 插件入口执行初始化并选择 `iab`，真实返回 `Local browser access is unavailable for this chat`。沿用已创建的连接读取恢复说明、只读列举浏览器，均返回同一错误。未打开目标页面、未获得截图、未切换其他控制机制，也未修改官方客户端或访问授权。因此当前页面验收明确为 **未通过 / 受当前对话本机浏览器访问阻断**，不能据网络探测、插件启用或服务就绪宣称通过。为何本对话不可访问尚未确定；需要新建本地对话后再实际复验，新对话是否能够恢复仍待验证。

后续顺序：

1. 已确认新官方客户端进程和电脑控制服务创建，兼容 PAC 有效。
2. 在新对话选择 Chrome，先验证能否读取用户已打开的订阅平台标签；接口缺失时记录为待验，不用其他自动化方式绕过。
3. 验证关闭兼容模式恢复旧 PAC 字段，再重新启用；退出 / 父进程消失的恢复单独验收。
4. 全部通过后再决定合入和发布。当前源码先保留在修复分支，避免把待验状态当正式发布。

## 回滚

旧版应用保存在用户本机 `~/Library/Application Support/CodexProxyLauncher/backups/20261111-native-compat/`。回滚前先通过新版“关闭并恢复原设置”结束兼容模式，确认系统 PAC 恢复，再还原旧应用。强杀助手时应先恢复管理员持有的 PAC 快照，不能直接删除恢复记录或留下失效 PAC 地址。
